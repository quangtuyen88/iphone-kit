# iPhoneKit v0.1.1 — experimental preview

This update hardens visual macro replay and recovery. It remains an experimental preview: physical reconnect, rotation, and Stop fault cases still need real-device validation.

## Changes

- Require fresh monotonic capture evidence before input, including a second screen check at the queued first-send boundary. Recheck phone identity, connection epoch, capture binding, geometry, and cancellation around asynchronous work.
- Check the full-screen context as well as the target crop. Context tolerance stays capped at 0.035 even when target matching is looser. Animations and background changes can pause replay.
- Keep Stop active until pending macro work and native input writes settle. Revoke dispatch authorization so a late validation result cannot authorize more input.
- Show the last visually verified step separately from the interrupted command's dispatch outcome. Require inspection and fresh review before a new run, which starts at step 1 and may repeat earlier effects. No automatic retry or resume.
- Reset review consent on every presentation and invalidate stale reviews after connection or recovery changes. Keep long safety notices scrollable with Cancel and Approve controls visible.
- Add a bounded, in-memory diagnostic trace without screenshots, OCR, phone identifiers, credentials, command payloads, or raw backend errors.
- Add regression coverage for stale frames, changed context, cancellation, input ownership, and Bluetooth write draining, plus an opt-in read-only live-capture probe.

These checks prevent further stale input when they detect a change; they cannot undo input already sent or guarantee detection of every overlay or last-moment screen change.

## Validation and limits

Sequential builds and the automated test suite pass. Offline checks cover the bundled REST and stdio MCP interfaces, macro recording/playback, private profile save/reload, and graceful shutdown. Native demo checks cover interrupted-run messaging, consent reset, both recovery acknowledgements, and readable review notices.

The read-only live-capture probe could not connect to a running real-phone API and did not validate hardware. Real Bluetooth disconnect/reconnect, rotation/capture rebinding, popup, and mid-gesture Stop tests remain unverified. Test-suite stalls and a cancellation-test timing race were corrected with controlled clocks and watchdog scheduling. Runtime deadline and timeout behavior is unchanged. See the [macro safety guide](https://github.com/quangtuyen88/iphone-kit/blob/v0.1.1/docs/MACRO-SAFETY.md) for the outstanding hardware matrix.

## Download and install

1. Download `iPhoneKit-0.1.1-macos-arm64.zip` and `SHA256SUMS` from this release. The ZIP contains `IPhoneKit.app` and its MCP helper for **Apple silicon**, not Intel Macs.
2. In the download directory, run `shasum -a 256 -c SHA256SUMS`.
3. Quit an existing copy with **Cmd+Q** before replacing it, so it can restore prior accessibility settings. Extract the ZIP and move the app to Applications.
4. Follow the USB trust, Camera, Bluetooth, and pairing instructions in the [README](https://github.com/quangtuyen88/iphone-kit/blob/v0.1.1/README.md).

The minimum build target is macOS 14.6. Earlier hardware testing used macOS 27 / iOS 27; older OS combinations remain unverified.

**Signing warning:** this preview is **ad-hoc signed and not notarized**, without Developer ID publisher verification. macOS may block it. Only if you trust the source and downloaded artifact, use **System Settings > Privacy & Security > Open Anyway** after attempting to open it. Do not disable Gatekeeper globally. Updates may require fresh Camera/Bluetooth permissions.

## Unchanged limitations

- TikTok search-result thumbnails ignored short HID clicks in earlier hardware tests. Mouse-report delivery is not proof that the intended touchscreen action occurred; verify the screen instead of blindly retrying.
- Pointer input requires portrait orientation. Multi-touch injection is unsupported; private Apple interfaces may break after OS updates.
- Keep purchases, messages, deletion, sign-in, and account changes out of automatic macro loops. Saved profiles contain full-screen reference JPEGs even when a matching region is cropped.
- Cloud-model tasks share screenshots, prompts, and recent actions with the configured provider. Live compatibility still needs testing with the chosen provider and explicit sharing consent.
- Older OS versions, multi-phone throughput, long unattended runs, and production notarized distribution are not certified.

## Source verification

Use Swift 6.2+ on macOS. Run `swift build` and `swift test` sequentially. Release artifacts are built from the committed source in an isolated directory, then extracted for owned demo integration checks. `scripts/verify-macros.py` and `scripts/verify-shutdown.py` accept `IPHONEKIT_APP_PATH`; `scripts/smoke-test.py` also needs an owned running demo instance. These checks must not send input to a real phone.
