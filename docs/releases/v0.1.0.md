# iPhoneKit v0.1.0 — experimental preview

The first iPhoneKit release: a local-first Mac app for observing and controlling a USB-connected iPhone through Bluetooth Classic HID. Nothing is installed on the phone; no jailbreak or Developer Mode is required.

## Included

- Native Mac UI with live USB screen capture, pointer gestures, US-ASCII keyboard input, Home, Stop, and opt-in Keep awake.
- Authenticated loopback REST API and bundled `iphonekit-mcp` stdio bridge.
- Optional vision-model agent chat using an OpenAI-compatible provider, explicit screenshot-sharing consent, Keychain credentials, and approval before every action.
- Local game-macro recording, private profile storage, visual/OCR guards, bounded playback, stop conditions, and exclusive input ownership.
- Offline demo mode and regression checks for input cancellation, connection epochs, HTTP security, macro behavior, and process shutdown.

## Download and install

- `iPhoneKit-0.1.0-macos-arm64.zip` contains `IPhoneKit.app`, including the MCP helper. This binary is for **Apple silicon**, not Intel Macs.
- The app declares macOS 14.6 as its minimum. Hardware behavior has been tested on macOS 27 / iOS 27; older OS versions remain unverified.
- Download `SHA256SUMS` beside the ZIP, then run `shasum -a 256 -c SHA256SUMS` in that directory.
- Extract the ZIP and move `IPhoneKit.app` to Applications. Quit an existing copy with Cmd+Q before replacing it, so it can restore prior accessibility settings.
- Launch the app and follow the USB trust, Camera, Bluetooth, and pairing instructions in the README.

**Signing warning:** this preview is **ad-hoc signed and not notarized**. It has no Developer ID publisher verification, and macOS may block it. Only if you trust the source and downloaded artifact, use **System Settings > Privacy & Security > Open Anyway** after attempting to open it. Do not disable Gatekeeper globally. Ad-hoc updates/rebuilds may require fresh Camera/Bluetooth permissions.

## Known limitations

- TikTok search-result thumbnails ignored short HID clicks in hardware testing even though tab navigation and a 1-second hold menu worked. This is unresolved; 150 ms and 250 ms presses did not fix it. These are mouse reports, not direct touchscreen contacts. `sent` confirms transport completion, not the intended UI result; verify with another screenshot and do not blindly retry.
- Pointer input requires portrait orientation. Multi-touch injection is not supported.
- Private Apple interfaces may break on OS updates. Multi-phone throughput, long unattended runs, older OS combinations, and production notarized distribution are not certified.
- Cloud-model compatibility needs a live test with your chosen provider and your explicit consent. Screenshots, prompts, and recent actions are shared with that provider during an authorized task.
- Saved macros contain full-screen reference JPEGs even when their matching region is cropped. Keep sensitive screens out of recordings.
- Visual guards and approval do not prevent every overlay or last-moment screen change. Keep purchases, messaging, deletion, and account changes out of automatic loops.
- No hosted cloud relay, remote/Streamable HTTP MCP, updater, or browser streaming is included.

## Build and verify from source

A Swift 6.2+ toolchain is required. Run `scripts/build-app.sh` before using the Python integration checks. `swift test`, `scripts/smoke-test.py` against an owned demo instance, `scripts/verify-macros.py`, and `scripts/verify-shutdown.py` cover the source and bundled front doors. Tests must not send input to real phones.

For isolated release checks, set `IPHONEKIT_APP_PATH` to a new bundle path for both the build script and Python checks, and set `CODESIGN_IDENTITY=-` for the build. This avoids overwriting an app currently controlling a phone. Notarization and Developer ID distribution are not part of this preview.
